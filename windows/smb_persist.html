WINDOWS SERVER MANAGEMENT



Introduzione
Questa procedura permette di collegare una cartella condivisa tramite protocollo SMB (Server Message Block) presente su un server Linux a un sistema Windows, assegnandole una lettera di unità, ad esempio Z:.

Una volta configurato il mapping, la share sarà accessibile da Windows tramite il percorso:

Z:\

Nell'esempio viene utilizzato il seguente scenario:

Server Linux: IP_DEL_SERVER_LINUX
Share SMB: nome_share
Utente: nomeutente
Unità Windows: Z:

Sostituire i valori di esempio con quelli effettivamente configurati sul server Linux.

Verificare la raggiungibilità del server
Prima di creare il mapping è consigliabile verificare che il server Linux sia raggiungibile dalla macchina Windows.

Aprire un Prompt dei comandi o PowerShell ed eseguire:
ping IP_DEL_SERVER_LINUX
Se il server risponde al ping, la connettività IP di base è disponibile.

Nota: il ping può essere disabilitato sul server Linux o sulla rete. In questo caso l'assenza di una risposta ICMP non significa necessariamente che il servizio SMB non sia raggiungibile.

Verificare la disponibilità della share SMB
È possibile verificare quali condivisioni SMB sono pubblicate dal server utilizzando il comando net view.

Eseguire:
net view \\IP_DEL_SERVER_LINUX
Se il server SMB è raggiungibile e consente l'enumerazione delle condivisioni, nell'output dovrebbe comparire anche la share nome_share.

Nota: alcuni server SMB possono impedire l'enumerazione delle share. In tal caso è comunque possibile che la condivisione sia accessibile direttamente specificandone il percorso.

Creare la share SMB persistente
Per creare il mapping della share SMB all'unità Z:, aprire un Prompt dei comandi e utilizzare il comando net use.

Il parametro /persistent:yes indica a Windows di mantenere il mapping anche dopo il riavvio del computer.
net use Z: \\IP_DEL_SERVER_LINUX\nome_share /user:nomeutente password /persistent:yes
Il comando è composto dai seguenti elementi:

Z: è la lettera di unità che verrà assegnata alla share.
\\IP_DEL_SERVER_LINUX\nome_share è il percorso UNC della condivisione SMB.
/user:nomeutente specifica l'utente utilizzato per autenticarsi al server SMB.
password rappresenta la password dell'utente SMB.
/persistent:yes rende persistente il mapping.

Importante: nell'esempio la password viene inserita direttamente nel comando. Questa modalità è comoda per un test, ma non è consigliata in ambienti reali perché la password può essere esposta nella cronologia, negli script o nei log.

Metodo consigliato: richiesta interattiva della password
Per evitare di inserire la password direttamente nel comando, è possibile utilizzare net use senza specificarla.

Windows richiederà quindi la password in modo interattivo.
net use Z: \\IP_DEL_SERVER_LINUX\nome_share /user:nomeutente /persistent:yes
Dopo l'esecuzione del comando verrà richiesta la password dell'utente nomeutente.

Questa modalità è preferibile quando si esegue manualmente la configurazione, perché evita di scrivere la password direttamente sulla riga di comando.

Verificare il mapping dell'unità
Dopo aver creato il mapping è possibile verificare le unità di rete configurate utilizzando:
net use
Nell'elenco dovrebbe comparire l'unità Z: associata al percorso UNC del server Linux.

È inoltre possibile verificare direttamente il contenuto dell'unità:
dir Z:\
Se il comando restituisce il contenuto della directory condivisa, il mapping è operativo e la share è accessibile.

Verificare la connessione SMB
Windows mette a disposizione il cmdlet PowerShell Get-SmbConnection per visualizzare le connessioni SMB attualmente attive.

Aprire PowerShell ed eseguire:
Get-SmbConnection
L'output permette di visualizzare informazioni sulla connessione SMB, tra cui il server remoto, la share, l'utente e il protocollo utilizzato.

Per ottenere un output più leggibile è possibile utilizzare:
Get-SmbConnection | Format-Table ServerName, ShareName, UserName, Dialect, NumOpens
In particolare:

ServerName: nome o indirizzo del server SMB.
ShareName: nome della condivisione SMB.
UserName: account utilizzato per la connessione.
Dialect: versione del protocollo SMB negoziata.
NumOpens: numero di handle aperti sulla connessione.

Verificare una specifica connessione
Se sono presenti numerose connessioni SMB, è possibile filtrare l'output per il server Linux specifico.
Get-SmbConnection | Where-Object ServerName -eq "IP_DEL_SERVER_LINUX"
In questo modo verranno visualizzate soltanto le connessioni SMB relative al server specificato.

Accedere alla share
Una volta configurato il mapping, la share può essere utilizzata come una normale unità locale.

È possibile verificare l'accesso tramite PowerShell:
Get-ChildItem Z:\
Oppure tramite Prompt dei comandi:
dir Z:\

Verificare la persistenza del mapping
Il parametro /persistent:yes utilizzato durante la creazione del mapping indica a Windows di memorizzare la connessione come persistente.

È possibile controllare le connessioni configurate con:
net use
Dopo un riavvio del computer, Windows tenterà di ristabilire il mapping dell'unità di rete.

Nota: la disponibilità effettiva della share dopo il riavvio dipende anche dalla raggiungibilità del server SMB e dalla disponibilità delle credenziali necessarie per l'autenticazione.

Rimuovere il mapping
Per rimuovere il mapping dell'unità Z: è possibile utilizzare:
net use Z: /delete
Windows chiederà conferma prima di rimuovere la connessione.

Per rimuovere il mapping senza richiesta di conferma:
net use Z: /delete /y

Rendere persistente una connessione esistente
Se una connessione è stata creata come temporanea, è possibile ricrearla come persistente utilizzando nuovamente net use con il parametro /persistent:yes.

Esempio:
net use Z: \\IP_DEL_SERVER_LINUX\nome_share /user:nomeutente /persistent:yes

Problemi di autenticazione
Windows normalmente non consente di utilizzare contemporaneamente, verso lo stesso server SMB, connessioni con credenziali differenti.

Se viene visualizzato un errore relativo a connessioni multiple con credenziali diverse, è possibile visualizzare le connessioni esistenti:
net use
Se necessario, rimuovere la connessione precedente e riprovare con le credenziali corrette.

Ad esempio:
net use \\IP_DEL_SERVER_LINUX\nome_share /delete

Verifica finale
Al termine della configurazione è consigliabile eseguire i seguenti controlli:

1. Verificare che il mapping Z: sia presente:
net use
2. Verificare che la share sia accessibile:
dir Z:\
3. Verificare la connessione SMB tramite PowerShell:
Get-SmbConnection | Format-Table ServerName, ShareName, UserName, Dialect, NumOpens
Se tutti i controlli hanno esito positivo, la share SMB Linux è stata correttamente collegata a Windows come unità Z: e configurata come connessione persistente.

Nota di sicurezza: evitare, quando possibile, di inserire password direttamente nei comandi o negli script. Utilizzare credenziali dedicate alla share e applicare sul server Linux i permessi SMB e filesystem minimi necessari.
